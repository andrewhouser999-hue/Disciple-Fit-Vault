# Covenant Identity — Between-Session Library — Phase-by-Scenario Deployment Strategy & Scrutiny

*Companion to [[Covenant Identity — Between-Session Library — Design Rationale]]. That document explains why each tool was built and how it works. This document answers a different question: for a specific client, in a specific phase, which tools deploy in which order — and where does the library currently have no answer at all. Built from a full-text read of every file in this folder, not from the index summaries.*

---

## How to Use This Document

1. **Locate the client's scenario** in the taxonomy below (Section 1).
2. **Open the phase the client is currently in** (Section 2) and read the deployment sequence for that scenario.
3. **Check the gap list** (Section 3) before assuming a tool covers the client's specific combination — several combinations have no purpose-built material and fall to a named interim substitute.
4. **Check the contradiction and pilot-status notes** (Section 3) before treating any two tools as interchangeable guidance.
5. This document does not replace the precondition logic embedded in each individual tool. It sequences and cross-references that logic; it does not restate all of it.

## Section 1 — Client Scenario Taxonomy

Between-session deployment in this library is governed by four axes. Not every axis applies at every phase (God-representation typing, for instance, is not yet stable in early Phase 1), but all four determine what is safe and formative to assign once they are known.

| Axis | Values | Established by |
|---|---|---|
| **Entry Fork** | Wound-Led / Vision-Led | Discovery Call, Diagnostic Lens Transition Logic Entry Fork addendum |
| **Wound Type** | Warrior / Hermit / False Noble / **No Wound Type Applies** (diffuse conditioning, no injury present) | [[Covenant Identity — Character Wound Diagnostic Tool]], gated by its own "Before Typing" injury check |
| **God-Representation Type** | Punitive / Absent-Distant / Permissive-Safe / Transactional / Capricious-Unsafe / Overwhelming-Consuming (six canonical types per the God-Representation Deepening Tool) | God-Representation Deepening Tool (in-session) |
| **Crisis/Distress Tier** | Tier 1 Normal / Tier 2 Distress / Tier 3 Crisis | [[Covenant Identity — Between-Session Distress Protocol]] — cross-cutting, can activate at any phase |

> **Not yet integrated (2026-09-05):** [[Covenant Identity — Externalization Noticing Practice]] (ALLk) was added to the library the same day as this note. It behaves like a fifth cross-cutting axis — presupposes none of the four above, can co-occur with any of them, deploys once named in session at any phase — but has not been run through this document's own scenario-coverage analysis (Section 3's full-text scrutiny method). Flagging rather than silently folding it in: deciding whether externalization warrants formal fifth-axis status, or stays a standalone recurring lens outside this taxonomy, is Andrew's call, not one to make by pattern-matching the existing four axes.

The full mathematical cross-product of these axes (2 × 4 × 6 × 3) is not a usable scenario list — most combinations are rare, and the library itself does not attempt that resolution. Below is the **adequate list**: every combination the library's own most rigorous cross-reference (P2c's Practitioner Precondition Check) already treats as clinically distinct, plus the combinations the scrutiny in Section 3 found to be structurally uncovered. Andrew should treat scenarios marked **Covered** as ready to deploy per Section 2, and scenarios marked **Gap** as requiring the interim substitute named in Section 3 until a purpose-built tool exists.

## Section 2 — Phase-by-Phase Deployment Strategy

### Phase 1 — Covenant Orientation

**Deploy to every client, regardless of scenario:**
- [[Covenant Identity — Pre-Session Preparation Guide]] (ALLb) — before Session 2, assigned once
- [[Covenant Identity — Formation Mechanism Guide]] (P1) — after the Gap is named, Session 1 or early Session 2; re-issuable if resistance resurfaces later
- [[Covenant Identity — Phase-Specific Reflection Guide]] (ALLd), Phase 1 section only
- [[Covenant Identity — Alliance Pulse]] (ALLe) — Session 1 onward; **pilot instrument, not a validated measure** (see Finding K) — read as a leading-indicator signal, not a diagnostic score
- [[Covenant Identity — Formation Self-Assessment]] (ALLg) — baseline administration at the end of Phase 1

**Deploy with restriction:**
- [[Covenant Identity — God-Representation Between-Session Practices]] (ALLj), Phase 1 section — **noticing only, no transformation practices.** This is a hard gate in the source document, not a suggestion.
- [[Covenant Identity — Scripture Saturation & Meditation Guide]] (ALLh), Phase 1 approaches — Gospel imagination (Approach 5) is barred until Phase 3.
- [[Covenant Identity — Spiritual Disciplines Guide]] (ALLi), Phase 1 section — 1-2 disciplines only, never a comprehensive list.

**Do not yet deploy:** any wound-type-specific tool (P2c, P2d, P2j, P3) or the Distress Protocol client card as a standing assignment — wound typing has not yet occurred, and P2a itself specifies it deploys at or before the first Phase 2 session, "contraindicated in Phase 1 unless risk indicators are present in intake or Discovery Call." If risk indicators are present, issue the Distress Protocol early regardless of phase; this is a scope-boundary judgment call, not a strict phase gate.

**Scenario note:** S11 (Vision-Led) has no distinct Phase 1 onboarding sequence anywhere in the library — the sequence above is the only one available and was written with Wound-Led framing throughout (the Formation Mechanism Guide's resistance section, for example, is organized entirely by wound type). Use it as-is until the future build named in Finding A exists, but do not force wound-type language onto a Vision-Led client during this phase.

### Phase 2 — Wound Mapping

**First, before any wound-specific material:**
1. [[Covenant Identity — Between-Session Distress Protocol]] (P2a) — issue at or before the first Phase 2 session. **Fill the coach-specified placeholders (response window, contact method) before handing this to a client** — the document ships with unfilled template fields; see Finding I.
2. [[Covenant Identity — Post-Session Client Debrief Card]] (ALLc) — given before Phase 2 begins, used after every session from this point forward.

**Once wound type is confirmed and acknowledged by the client** (S1-S10):
3. Run the Practitioner Precondition Check in [[Covenant Identity — Character Wound Between-Session Practices]] (P2c) against the client's God-representation type — see Section 1's scenario table for the specific precondition required.
4. Deploy P2c's Phase 2 section for the confirmed wound type.
5. [[Covenant Identity — Lament Practice Guide]] (P2e) — give the theological container in session first; the client's God-representation must permit honest address before this is assigned (thin for S13/Permissive-Safe — see Finding D). Phase 2 psalm selection holds lament without forced resolution (Ps 88, 13:1-4, 73:1-16).
6. [[Covenant Identity — Accountability Companion Guide]] (P2g) — once wound work has begun; not before, not later than Phase 3.
7. [[Covenant Identity — Deep Lie Work Worksheet]] (P2j) — only once wound mapping has surfaced a specific lie and schema; there is no Phase 1 version and no non-injury version (see Finding C).
8. [[Covenant Identity — Post-Session Integration Guide]] (P2d) — after any particularly heavy Phase 2 session, once wound type is identified. **This document hard-gates on wound type with no fallback** — see Finding B for what to do with an S12 client.
9. If Stage 4b implicit-level work opens: [[What the Part Carries — An Independent Formation Practice]] (P2k), gated by its own embedded Activation and safety-stop requirements.

**If wound type does not resolve (S12, No Wound Type Applies):**
Follow P2c's own 2026-07-14 redirect: assign from [[Covenant Identity — God-Representation Between-Session Practices]], [[Covenant Identity — Lament Practice Guide]], [[Covenant Identity — Spiritual Disciplines Guide]], [[Covenant Identity — Scripture Saturation & Meditation Guide]], and [[Covenant Identity — Formation Self-Assessment]] — all five are wound-type-independent at their core. For the Post-Session Integration Guide's uncovered heavy-session case (Finding B), the interim substitute is to use the Integration Guide's four biblical precedents (Elijah, Moses, Jacob, Transfiguration) and its ordered-practices structure generically, without selecting a wound-type "What You May Experience" section — the precedents and practice order are not themselves wound-type-dependent, only the framing language around them is.

**Warrior-specific note (resolves Finding G):** [[Covenant Identity — Phase-Specific Reflection Guide]] (ALLd) treats Warrior Phase 2 journaling as assignable with a 10-minute cap. [[Covenant Identity — Character Wound Between-Session Practices]] (P2c) treats it as contraindicated by default, with a narrow exception only for a Warrior who entered with an established somatic-noticing journaling practice. **P2c governs** — its guidance is wound-type-specific and reasoned from the Warrior's re-armoring pattern, while ALLd's guidance is a generic phase-level default that was not written with the Warrior pattern in view. Until Andrew adds a cross-reference note to ALLd, treat any Warrior client's Phase 2 journaling assignment as contraindicated by default.

### Phase 3 — Identity Installation

**Deploy for confirmed wound types (S1-S10):**
- P2c Phase 3 section for the confirmed wound type — installation-mode practices; do not deploy Phase 2 excavation-supportive practices here, and do not deploy Phase 3 installation practices in Phase 2 (P2c's own load-bearing phase-matching rule).
- [[Covenant Identity — Deep Identity Installation Worksheet]] (P3) — after P2j; Part 5 (Relational Ecology) has its own entry criteria and should not be worked in the same sitting as Parts 1-3.
- [[Covenant Identity — God-Representation Between-Session Practices]] (ALLj), Phase 3 section — this is the library's **primary transformation mechanism**, built around the Gospel Encounter Library. Deploy the passage cross-referenced to the client's specific God-rep type.
- [[Covenant Identity — Scripture Saturation & Meditation Guide]] (ALLh) — Gospel imagination (Approach 5) unlocks here; still contraindicated for Overwhelming/Consuming God-rep until encounter safety is established.
- [[Covenant Identity — New Covenant Promise Map 1]] (P2i) — routing table covers Punitive, Absent/Distant, Transactional, and Capricious/Unsafe only. For S13 (Permissive/Safe) and Overwhelming/Consuming clients, the table's own instruction applies: "the client's own language overrides the table" — select promise categories from session material directly rather than the routing table.
- [[Covenant Identity — Lament Practice Guide]] (P2e), Phase 3 psalm set — lament moving toward trust (Ps 22 full, 42, 77).

**Scenario note:** this is the phase where God-representation coverage gaps (Finding D, S13) matter most, since Phase 3 is explicitly where God-rep transformation work is front-loaded. A Permissive/Safe client in Phase 3 has the least calibrated support of any God-rep type in the library at exactly the phase where that calibration carries the most weight.

## Crisis Tier Overlay (S15 — cross-cutting, any phase)

Tier definitions and the escalation path live entirely in [[Covenant Identity — Between-Session Distress Protocol]] (P2a):
- **Tier 1 (Normal Processing):** self-settling within 24-48 hours; no coach contact needed beyond standard between-session material.
- **Tier 2 (Between-Session Distress):** elevated, not crisis; client card triage sequence (danger-check first, then body, then coach contact); coach bridge call is containment only — explicitly prohibited from excavating or opening new material.
- **Tier 3 (Crisis):** escalate immediately to [[Covenant Identity — Crisis & Referral Protocol]]; P2a explicitly defers rather than attempting to hold this itself.

**Before this protocol can be handed to a client, the coach-specified placeholders (acknowledgment window, contact method, response form) must be filled in.** As written, the document is not deployment-complete — see Finding I.

**Frequency-of-use is itself diagnostic**, per P2a: two or more Tier 2 activations in a month signals the engagement is moving faster than the client's window of tolerance, or that the material is clinical in depth — not a cue to optimize the protocol's wording.

## Section 3 — Scrutiny Findings

Findings are ordered by how much they constrain safe or complete deployment, not alphabetically.

### A. Structural gap — no Vision-Led pathway exists anywhere in this folder
The term "Vision-Led" does not appear in any of the 22 files. Every between-session tool that branches content (wound-type practices, God-rep practices, the Formation Mechanism Guide's resistance section) is written with Wound-Led, injury-driven framing as the implicit default. P2c's "If No Wound Type Applies" section (added 2026-07-14) is the closest thing to an accommodation, but it frames non-typing as *wound-mapping that didn't resolve to a type* — a variant within the Wound-Led paradigm — not as a structurally distinct, growth-driven entry pathway with its own between-session logic. A client who entered through the Vision-Led door (per [[Covenant Identity — Wound-Led vs. Vision-Led — Architecture at a Glance]]) has no dedicated between-session onboarding, sequencing, or practice library anywhere in this system. This is the single largest coverage hole in the between-session library and affects Phases 1 through 3.

### B. Structural gap — Post-Session Integration Guide (P2d) has no non-injury fallback
P2d states explicitly: "Do not give this guide before the client's wound type has been identified." Unlike P2c, which built a redirect list for this exact situation, P2d offers no substitute. An S12 (No Wound Type Applies) client who has a heavy session currently has no calibrated 24-48-hour integration guide naming their experience. Section 2's Phase 2 entry above names an interim workaround (use the four biblical precedents and the practice order generically, without the wound-type framing sections); this is a stopgap, not a fix.

### C. Structural gap — Deep Lie Work Worksheet (P2j) also has no non-injury path
P2j's own entry signal requires "wound mapping has already surfaced the specific lie and schema" and states plainly "there is no Phase 1 version." No document in the library explains how lie-and-schema work proceeds for a client who never resolves to a confirmed wound type. This compounds Finding A: a Vision-Led or non-injury client's path through Phase 2-3 lie/identity work is currently undefined at exactly the tools that carry the most formation weight.

### D. Coverage gap — Permissive/Safe God-rep type is thin across the library
Full calibration exists in only 2 of the 9 God-rep-organized documents (ALLj, P2b). It is absent from the Phase-Specific Reflection Guide's calibration notes, the Scripture Saturation Guide's Section V table, the Spiritual Disciplines Guide's Section VI table, the Lament Practice Guide's precondition table, and the New Covenant Promise Map's routing table. A Permissive/Safe client falls to generic/universal guidance across most of the library's calibrated tools — the opposite problem from the other five God-rep types, which are consistently well-covered.

### E. Coverage gap — Overwhelming/Consuming God-rep is similarly thin outside four documents
Present in ALLj, P2b, ALLh, and ALLi; absent from P2e's lament precondition table and P2i's promise-map routing table. Less severe than Finding D since more documents cover it, but the same pattern of inconsistent inclusion applies.

### F. Coverage gap — P2c's own precondition table leaves 5 of ~15-18 combinations unanalyzed
P2c's Practitioner Precondition Check (the most rigorous wound×God-rep cross-reference in the library, reproduced in Section 1's scenario table as S1-S10) covers 9 combinations. Warrior×Permissive/Safe, Warrior×Overwhelming/Consuming, Hermit×Punitive, False Noble×Punitive, and False Noble×Overwhelming/Consuming (S14) do not appear. It is currently impossible to tell from the document whether their absence means "reviewed and found no elevated risk" or "not yet analyzed" — the two read identically on the page. This should be resolved explicitly rather than left silent, since a coach encountering one of these five combinations has no way to know whether the omission is a safety judgment or a gap.

### G. Contradiction — Warrior Phase 2 journaling (ALLd vs. P2c)
Already resolved operationally in Section 2's Phase 2 entry above (P2c governs). Flagging here as a scrutiny finding because the two documents do not cross-reference each other on this point, so the contradiction is invisible unless both files are read side by side — which this document now makes unnecessary going forward, but the source documents themselves still disagree in isolation.

### H. Terminology drift — God-representation type count and naming are inconsistent across the library
ALLj and P2b use the full 6-type canonical model (adding Overwhelming/Consuming to the original 5, per the God-Representation Deepening Tool). ALLd, ALLh, ALLi, and P2e use a 5-type subset that consistently drops Permissive/Safe — which likely explains Finding D rather than being an independent problem: if a document's type list never includes Permissive/Safe, it structurally cannot calibrate for it. P2i's routing table uses only 4 types, dropping both Permissive/Safe and Overwhelming/Consuming. Separately, P2b uses different labels for the same underlying types ("Punishing God Type," "Contingent/Transactional God Type") than the ALLj/ALLh/ALLi/P2e/P2i convention ("Punitive," "Transactional"). A coach cross-referencing P2b against any other document currently has to manually map the naming. No theological or clinical content was found to actually contradict across these documents — this is a coverage-and-naming inconsistency, not a substantive disagreement.

### I. Deployment-readiness gap — Between-Session Distress Protocol (P2a) ships with unfilled placeholders
Both the practitioner section and the client card contain bracketed coach-specified fields (e.g., "[COACH SPECIFIES: 24 hours / same business day / etc.]") for response window and contact method. As written, the document cannot be handed to a client — this is a one-time setup task, not a per-client customization, and should be completed before the next between-session material is issued to any Phase 2+ client.

### J. Metadata gap — New Covenant Promise Map Generation Prompt (P2h) has incomplete frontmatter
`basis: TBD` and a blank `created` field, out of step with the vault's own basis-frontmatter standard applied everywhere else in this folder. Low priority relative to Findings A-I but a quick fix.

### K. Pilot status — Alliance Pulse (ALLe) is not yet a validated instrument
Self-flagged in the source document: "no published reliability or validity numbers of its own," not yet included in the System Document Master List, Document Reading Order, or Coaching Agreement. Section 2 above includes it as a Phase 1+ deployment because it is already in active pilot use, but its readings should be treated as a leading-indicator signal, not a scored diagnostic, until Andrew's own stated promotion criterion is met (first alpha client completes a full engagement with good response rate and useful trend data).
